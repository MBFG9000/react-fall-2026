Sequential vs Concurrent

Sequential uses await task1.run() one after another. Concurrent uses Promise.allSettled([...]) to start everything at once.

Why the results are different:

  • Sequential: each await pauses the function until that task settles, so the timers run one after another. Total time ≈ sum of all delays.
  • Concurrent: all run() calls are made before any await, so all three setTimeout timers are registered at the same moment and count down in parallel. Total time ≈ the longest single delay.
  • JavaScript is single-threaded, but waiting is not done by JavaScript — the timers are handled by the browser, so the delays can overlap.

Explanation: Call Stack → Microtask Queue → Task Queue → Event Loop

  • Call Stack: the synchronous lines run first — "1 script start", "2 async start" (an async function body runs synchronously until the first await) and "7 script end".
  • Task Queue (macrotasks): both setTimeout callbacks are handed to the browser's timer API. Even with 0 ms they only go into the task queue, they never jump the line.
  • Microtask Queue: .then() callbacks and everything after an await are microtasks. When the stack becomes empty the event loop drains the whole microtask queue first — so "3 await resolved", "4 promise then 1", "5 promise then 2" and "6 chained then" all run before any timer.
  • Event Loop: only after the microtask queue is empty does it take one task from the task queue — "8 timeout 0" — drains microtasks again ("9 microtask from timeout"), and then takes the next task, "10 timeout 10".
